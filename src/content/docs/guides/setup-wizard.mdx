**Goal:** Turn the freshly extracted paid theme into *your* site without hand-editing configuration files.

<Aside type="note" title="Paid theme only">
  The setup wizard ships embedded in the **paid theme**. Using the free starter theme? Configure it by hand instead — the [Getting Started guide](/getting-started/) walks you through the same files in about 10 minutes.
</Aside>

## Start the wizard <sup>1 minute</sup>

<Steps>

1. **Extract the purchased ZIP** and open a terminal in the extracted folder

2. **Install dependencies**

   ```bash
   npm install
   ```

3. **Start the dev server**

   ```bash
   npm run dev
   ```

4. **Open the wizard** at [http://localhost:4321/setup](http://localhost:4321/setup)

</Steps>

The wizard only runs on the local dev server. It is never part of your deployed site: the `/setup` pages are kept out of production builds and the file-writing endpoint refuses to run outside development.

## The steps

Your progress is saved in the browser as you go — if you close the tab, reopening `/setup` offers to resume where you left off.

1. **Welcome** — what the wizard will do, and a resume option if you've been here before.
2. **Company information** — name, address, PO box, city, phone, email, Google Maps link and social profiles (LinkedIn, Facebook, Instagram, X/Twitter, GitHub).
3. **Website settings** — your site URL, the primary language, any additional languages, and the site title and description per language.
4. **Team & analytics** — team members (name, contact details, socials) and an optional Google Tag Manager ID.
5. **Review & generate** — a summary of everything you entered. Click **Generate Configuration** to write the files.

<Aside type="caution" title="Language choices">
  The language picker offers many languages, but the theme ships translations for **French, German and English**. Picking an unsupported language is rejected with a validation error at the generate step. To genuinely add another language, follow the [Adding Languages guide](/guides/adding-languages/) after the wizard.
</Aside>

## What it writes

Generating the configuration touches exactly three files:

| File | Contents |
|---|---|
| `src/consts.ts` | Company information and team members (`COMPANY`, `EMPLOYEES`) |
| `src/i18n/ui.ts` | Language list, default language, site title and description per language |
| `.env` | Site URL, default language, GTM ID (if provided) |

Before writing, the wizard backs up each existing file to a timestamped copy in `.wizard-backups/` at the project root, so a wizard run is never destructive.

<Aside type="caution" title="ui.ts is fully replaced — restore the theme dictionary">
  The generated `src/i18n/ui.ts` contains **only** your site title and description per language. The theme's full translation dictionary (`nav.*`, `services.*`, button labels, …) is not carried over, so navigation and section labels will fall back to raw keys after a wizard run.

  **Fix:** open the backup in `.wizard-backups/` (e.g. `ui.<timestamp>.ts.backup`) and copy every key **except** `site.title` and `site.description` back into the generated `ui.ts`. This is a one-time merge after generating.
</Aside>

## After the wizard

Restart the dev server so the generated `.env` is picked up, then check your site at [http://localhost:4321](http://localhost:4321).

From here the docs apply to both themes:

- [Configuration](/guides/configuration/) — everything the wizard wrote, explained file by file
- [Customization](/guides/customization/) — logo, colors, content
- [Adding Languages](/guides/adding-languages/) — extend beyond FR/DE/EN
- [Deployment](/deployment/) — go live (the wizard never ships with the deployed site)

You can re-run the wizard at any time — each run creates fresh backups first.
